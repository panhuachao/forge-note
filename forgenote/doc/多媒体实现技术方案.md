# 多媒体实现技术方案

> 适用范围：Markdown 笔记中的**图片**（编写时复制粘贴）与**音频**（未来语音录入 → 自动转译 → 生成文本笔记）。
> 设计原则与《Markdown 笔记重构方案》一致：**笔记文件是唯一真源**，多媒体以独立文件落盘到知识库（KB）内，通过相对路径引用；SQLite 仅作为检索加速副本，在文件变动后自动派生。

---

## 1. 总体设计

### 1.1 存储位置

在 **KB 根目录**下建立**统一个**资源仓库 `.assets/`，内部按媒体类型划分子目录，所有笔记共享，不随单篇笔记就近存放：

```
<KB 根>/
├── .assets/                    # 统一资源仓库（按内容 hash 去重存储）
│   ├── image/
│   │   ├── a1b2c3d4e5f6....png   # 文件名 = 内容 hash + 原扩展名
│   │   └── 9f8e7d6c5b4a....jpg
│   └── audio/
│       └── d4e5f6a7b8c9....m4a
├── 00 灵感库/
│   └── 会议记录.md
└── ...
```

设计要点：
- **统一目录**：单一 `.assets/` 收纳全部资源，避免每篇笔记各自带 `.assets` 目录、难以复用。
- **按类型分子目录**：`image/`、`audio/`（未来可加 `video/`、`file/`），便于批量管理与清理。
- **按内容 hash 命名**：文件名即文件内容的 SHA-256（或截断至 16~32 位）十六进制串 + 原扩展名。**相同二进制内容永远映射到同一文件**，复制粘贴同一张图不会产生冗余副本。
- 迁移：拷贝整个 KB 文件夹（含 `.assets/`）即可完整迁移，零丢失。

### 1.2 引用方式

Markdown 正文内使用**相对于笔记所在目录**的路径引用 `.assets/...`，通用工具（Obsidian/VSCode）可直接预览：

```markdown
![截图](../.assets/image/a1b2c3d4e5f6....png)
```

> 引用统一指向根级 `.assets/`，与笔记所在子目录深度无关（用 `../` 或绝对仓库相对路径解析）。

音频未来以链接/卡片形式引用，并保留原始文件 + 生成的文本笔记双链：

```markdown
- 🔊 语音录入： [d4e5f6a7b8c9....m4a](../.assets/audio/d4e5f6a7b8c9....m4a)
```

### 1.3 命名规则

- 图片：`<sha256(内容前N字节+大小)[:32]>.<原扩展名>`，如 `a1b2c3d4e5f6....png`，存于 `.assets/image/`。
- 音频：同 hash 规则，存于 `.assets/audio/`，如 `d4e5f6a7b8c9....m4a`。
- 转译文本笔记：`a1b2....transcript.md`，与音频**同处 `.assets/audio/`** 或独立 `.assets/transcripts/`，作为独立笔记自动入库（文件名同样由音频内容 hash 派生，保证音频与其转写一一对应、且不重复生成）。
- hash 计算应覆盖完整二进制（或前 1MB + 文件大小），兼顾去重强度与性能。

## 2. 文件存储流程（图片：复制粘贴）

### 2.1 数据流

```mermaid
flowchart TD
  A[编辑器粘贴图片] --> B[renderer: 读取剪贴板 Uint8Array]
  B --> C[preload: forge.media.saveImage(kbId, notePath, buf, ext)]
  C --> D[main: fs-service.saveAsset]
  D --> E[写入 .assets/image/<hash>.png（去重）]
  E --> F[返回相对引用路径]
  F --> G[renderer: 在光标处插入 ![alt](相对路径)]
  G --> H[writeNote 落盘 + syncIndex]
```

### 2.2 实现要点

1. **renderer 侧**：监听编辑器 `paste` 事件；若为图片，取 `clipboard.readImage().toPNG()`（或原生文件的 ArrayBuffer），经 `preload` 调主进程保存。
2. **主进程 `fs-service.saveAsset(kbId, buffer, ext, kind)`**（按内容 hash 去重，与具体笔记解耦）：
   - `kind` ∈ `image | audio`，决定子目录 `.assets/image` 或 `.assets/audio`。
   - 计算内容 hash：`h = sha256(buffer).slice(0, 32)`，目标文件名 `h + '.' + ext`。
   - `destDir = safeJoin(root, '.assets', kind)`，`mkdirSync(recursive)`。
   - **去重核心**：`dest = join(destDir, h + '.' + ext)`；若 `existsSync(dest)` 直接复用，跳过写入（相同内容只存一份）；否则 `atomicWrite(dest, buffer)`。
   - 返回**相对于仓库根**的引用路径（如 `.assets/image/a1b2c3....png`），渲染时按笔记位置归一化为相对链接。
3. **不写入 SQLite**：资源文件本身不入 `note_meta`/全文索引；仅其引用文本随正文被索引。图片 alt/音频文件名不计入检索噪声。
4. **引用统一指向根级 `.assets`**：无论笔记在哪个子目录，引用都解析为根级 `.assets/...`，避免笔记移动后路径失效。

## 3. 音频录入 → 转译 → 文本笔记

### 3.1 数据流

```mermaid
flowchart TD
  A[用户点击「语音录入」开始] --> B[renderer: MediaRecorder 采集音频 Blob]
  B --> C[停止录制]
  C --> D[preload: forge.media.saveAudio(kbId, notePath, blob)]
  D --> E[main: 落盘 .assets/audio/<hash>.m4a（去重）]
  E --> F[main: ai-service.transcribe(audioAbs)]
  F --> G[生成 <hash>.transcript.md（含 Front Matter: source=audio, tags）]
  G --> H[syncIndex 自动入库 + 在原笔记插入语音链接]
```

### 3.2 实现要点

1. **采集**：renderer 用 `navigator.mediaDevices.getUserMedia` + `MediaRecorder` 录制，停止后拿到 `Blob`/`ArrayBuffer`。
2. **保存音频**：同 §2.2 的 `saveAsset(kbId, buffer, ext, 'audio')`，存为 `.assets/audio/<hash>.m4a`（内容 hash 去重，重复录制同一段音频不会新增文件）。
3. **转译**：新增 `ai-service.transcribe(audioAbs)`，调用 ASR（本地 Whisper / 云端 STT）。返回纯文本。
4. **生成文本笔记**：
   - 文件名由**音频内容 hash** 派生：`.assets/audio/<hash>.transcript.md`，保证音频与其转写一一对应、重复转译不重复生成。
   - Front Matter 遵循现有标准（见《Markdown 笔记重构方案》§2），并**扩展 `source` 字段**（已在 `writeFrontmatter` 预留保留能力）：

     ```markdown
     ---
     title: 语音转写 2026-08-28
     summary: 自动转写的语音笔记
     tags: [语音, 转写]
     source: audio:.assets/audio/d4e5f6a7b8c9....m4a
     ---

     转写正文……
     ```
   - 通过 `writeFrontmatter(content, { title, summary, tags, source })` 生成，确保不破坏其他字段。
5. **自动入库**：生成后调用 `fs-service.syncIndex(kbId, transcriptPath)`，触发 `search-service.upsertNote`，SQLite `note_meta` 的 `summary/tags/(未来)source` 自动派生。
6. **回链原笔记**：在原笔记尾部或光标处插入引用链接（如 `🔊 [语音转写](../.assets/audio/<hash>.transcript.md)`），可选双链。

## 4. 与主架构的衔接

| 能力 | 现状 | 多媒体扩展 |
| --- | --- | --- |
| 文件写入 | `atomicWrite` | 复用，支持 Buffer 写入资源 |
| Front Matter | `writeFrontmatter` 保留扩展字段 | `source: audio:...` 直接兼容 |
| 索引同步 | `syncIndex` → `upsertNote` 从文件派生 | 资源引用随正文索引；转写笔记作为普通笔记入库 |
| 迁移 | 拷贝 KB 文件夹 | `.assets/` 随 KB 根一起迁移，整体零丢失 |
| 检索 | SQLite `note_meta` 副本 | 转写文本笔记参与全文检索，音频文件本身不参与 |

**关键不变量**：无论是图片粘贴还是音频转写，最终都先落盘为 KB 内的真实文件，再由既有的 `syncIndex` 自动更新 SQLite。不在生成阶段直接写库，符合「文件为真源」原则。

## 5. 边界与一致性

1. **笔记重命名/移动**：因资源统一存于根级 `.assets/` 且与笔记名解耦，**重命名/移动笔记无需触碰资源目录**，只需把正文内 `../.assets/...` 引用调整为相对新位置（或统一改用仓库相对路径 `.assets/...` 存储，移动零影响）。
2. **引用路径归一化**：存储时统一记为仓库相对路径 `.assets/image/<hash>.png`；渲染时由笔记实际位置换算为 `../.assets/...` 或直接用仓库锚点，确保任意层级笔记均可正确预览。
3. **孤立资源清理**：由于 hash 去重，同一资源可能被多篇笔记引用；提供「清理未引用资源」工具，扫描全部 `.md` 引用集合，删除 `.assets/` 中无引用的文件（谨慎、可预览后再删）。
4. **引用校验**：`readNote` 返回的 `brokenLinks` 目前只校验 `[[wikilink]]`；后续可扩展校验 `![](相对图片)` / 音频链接是否存在，给出失效资源提示。
5. **体积控制**：图片粘贴可默认限制单张 ≤ 10MB，过大提示先压缩；音频建议转码为 m4a/aac 以省空间。
5. **并发安全**：资源写入均经 `atomicWrite`，避免同一笔记并发粘贴导致半截文件。

## 6. 接口草稿（preload / main）

```ts
// preload: window.forge.media
interface MediaService {
  // 返回仓库相对引用路径，如 .assets/image/<hash>.png（内容相同则复用同一文件）
  saveImage(kbId: string, buf: Uint8Array, ext: string): Promise<string>;
  saveAudio(kbId: string, buf: Uint8Array, ext: string): Promise<string>;
}

// main: fs-service
// kind 决定子目录；文件名按内容 hash 派生并去重；返回仓库相对引用路径
saveAsset(kbId: string, kind: 'image' | 'audio', data: Uint8Array, ext: string): Promise<string>

// main: ai-service
transcribe(audioAbs: string): Promise<string /* 转写纯文本 */>
generateTranscriptNote(kbId: string, audioRelPath: string, text: string): Promise<string /* transcript 笔记路径 */>
```

## 7. 后续扩展

1. **语音录入实时流式转写**：边录边传分片，降低结束后的等待。
2. **图片 OCR / 多模态理解**：粘贴图片后可选 AI 提取图中文字或生成描述，写入笔记摘要/标签。
3. **资源仓库集中管理页**：在左侧/资源面板列出 KB 内所有图片、音频，支持预览、批量清理孤立资源。
4. **云端同步**：资源文件与 `.md` 一并纳入同步策略（如 Git / 对象存储），保持引用一致。
