# 锦囊笔记 · 用户画像实现方案

> 版本：v1.0（草案）
> 目标：构建一个**持续演进的用户画像（User Profile）**，在用户与 AI 的每一次交互中积累、修正、完善；并在后续所有 AI 协作（聊天问答 / 笔记对话 / 知识库诊断 / 智能写作 / 灵感工坊等）中作为「长期记忆与个性化上下文」注入，让 AI 知识管家越来越懂用户。
> 定位：用户画像是「AI 调用重构技术方案」中 `AIHub` 之上的**一层持久化上下文**，与 `Session`（短期多轮记忆）、`PromptRegistry`（提示词治理）、`MCP Tool`（知识库操作）正交协作。

---

## 1. 设计原则

1. **隐私优先、本地优先**：画像数据全部存储在本地（知识库 `.forge/user-profile.json` 或 app 级配置），不上传任何云端；用户可随时查看、编辑、清空。
2. **可解释、可追溯**：每次画像更新都记录「触发来源」（哪次交互、哪个 Skill、哪条证据），支持回看与撤销。
3. **增量、低侵入**：画像更新走「异步、轻量、离线可」的抽取通道，不阻塞主对话延迟；抽取出错不影响主流程。
4. **与现有体系一致**：复用 `AIHub` 的 Skill 机制（画像抽取 = 一个 `Skill`）、`Session` 历史（短期上下文）、`AIService` 的 LLM 调用；不另起炉灶。
5. **用户可接管**：画像中的「事实类」字段（如职业、关注领域）可由用户手动修正，AI 仅作建议，最终以用户确认为准（承接「先建议后确认」铁律）。

## 2. 用户画像数据模型

### 2.1 顶层结构

```ts
// shared/types/profile.ts
export interface UserProfile {
  /** 画像 schema 版本，迁移用 */
  version: number;

  /** 基础信息（多为用户填写 / 可手动修正的事实类） */
  basics: ProfileBasics;

  /** 兴趣与关注主题（动态，来源：笔记标签、对话、诊断） */
  interests: ProfileTopic[];

  /** 用户画像长文本（由 LLM 归纳的一段自然语料，供注入 system 提示词） */
  persona: string;

  /** 协作偏好（AI 应如何与用户打交道） */
  preferences: CollaborationPreference;

  /** 能力 / 知识背景评估（动态，用于调整回答深度） */
  expertise: ExpertiseMap;

  /** 近期关注与上下文（短期信号，会随时间衰减） */
  recentFocus: RecentFocusEntry[];

  /** 画像更新审计 */
  audit: ProfileAuditEntry[];

  /** 画像整体置信度 0~1（用于决定是否注入 / 提示用户补全） */
  confidence: number;

  updatedAt: number;
}
```

### 2.2 子结构定义

```ts
export interface ProfileBasics {
  name?: string;            // 用户昵称（可选）
  role?: string;            // 职业 / 身份，如「产品经理」「独立开发者」
  domains?: string[];       // 长期关注领域，如 ['AI','个人知识管理']
  goals?: string[];         // 当前目标，如 ['搭建第二大脑','输出技术博客']
  timezone?: string;        // 时区（用于每日灵感节奏）
  language?: string;        // 偏好的回答语言，默认中文
}

export interface ProfileTopic {
  name: string;             // 主题名，与笔记标签体系打通
  weight: number;           // 0~1 关注度（根据出现频率 / 对话提及衰减计算）
  firstSeen: number;
  lastSeen: number;
  evidence: string;         // 最近一次证据摘要（如「在 12 篇笔记中出现」「对话中多次询问」）
  source: TopicSource;      // 'note-tag' | 'chat' | 'diagnose' | 'manual'
}

export interface CollaborationPreference {
  tone: 'concise' | 'detailed' | 'socratic' | 'casual'; // 回答风格
  proactivity: 'passive' | 'balanced' | 'proactive';    // 主动建议程度
  depth: 'intro' | 'intermediate' | 'expert';           // 默认深度
  citeSources: boolean;                                  // 是否要求引用笔记来源
  autoSummarize: boolean;                                // 是否自动摘要长笔记
  preferStructured: boolean;                             // 结果是否偏好结构化（列表/卡片）
}

export interface ExpertiseMap {
  /** 领域 -> 自评估等级 0~5 */
  [domain: string]: number;
}

export interface RecentFocusEntry {
  topic: string;
  weight: number;
  ts: number;
  decayed: boolean;
}

export interface ProfileAuditEntry {
  ts: number;
  skill: string;            // 触发抽取的 skill（ask / diagnose / ...）
  field: string;            // 被更新的字段路径，如 'interests[AI].weight'
  delta: string;            // 变更说明
  confidenceDelta: number;  // 本次对整体置信度的贡献
}
```

### 2.3 持久化位置

- **知识库级**：`<kb>/.forge/user-profile.json` —— 与知识库强相关（兴趣、领域、诊断结论），跟随知识库迁移。
- **App 级**（跨库通用偏好）：`app_config` 的 `user:profile-base` —— `basics` 中的 `name`/`language`/`timezone`、`preferences` 默认偏好等。
- 读取时：**App 级作为底，知识库级叠加覆盖**；写回时按归属落盘。

## 3. 架构与数据流

```
┌─────────────────────────── 渲染进程 ───────────────────────────┐
│  UI（ChatPage / NoteAIChat / DiagnosePage / 灵感工坊 ...）        │
│        │ 正常对话                                                 │
│        ▼                                                         │
│  useAI() / useAISession()  ── 调用 AIHub                         │
│        │                          │                              │
│        │            ┌─────────────┴──────────────┐               │
│        │            │  AIHub（统一编排）           │               │
│        │            │   ├─ 注入 UserProfile → system │ ◄──┐       │
│        │            │   ├─ Skill 执行              │    │       │
│        │            │   └─ 调用 ProfileExtractor  │ ──┐│       │
│        │            └─────────────────────────────┘   ││       │
└────────┼────────────────────────────────────────────────┼┼──────┘
         │ IPC                                              ││
┌────────▼──────────────────── 主进程 ──────────────────────▼┐│
│  profile-service.ts（画像读写 / 合并 / 衰减）                 ││
│  profile-extract-skill.ts（Skill：从对话/笔记抽取画像） ◄─────┘│
│  ai-service.ts / AIHub（对话 + 注入画像到 system 提示词）      │
└──────────────────────────────────────────────────────────────┘
```

**闭环要点**：
1. 每次 AI 请求前，`AIHub` 从 `profile-service` 读取当前画像，渲染成一段 `system` 附加上下文（见 §5）。
2. 每次 AI 响应后（或会话阶段性结束时），`AIHub` 异步触发 `profile-extract-skill`，把本轮 `user/assistant` 文本喂给抽取 Skill，产出「画像增量」。
3. `profile-service` 合并增量（带衰减、去冲突、计审计），落盘。

## 4. 画像提取 Skill（核心能力）

画像抽取本身实现为一个**内置 Skill**，完全复用 `AI调用重构技术方案` 的 Skill 机制，零主进程骨架改动。

### 4.1 Skill 声明

```ts
{
  id: 'profile-extract',
  title: '用户画像抽取',
  description: '从一次交互（对话/诊断结果/笔记元信息）中抽取用户画像增量',
  capability: ['cheap'],        // 用最便宜的模型即可，抽取是结构化小任务
  stateful: false,
  inputSchema: {
    history: 'AITurn[]',         // 本轮交互历史
    trigger: 'ask' | 'diagnose' | 'note-save' | 'forge' | 'manual',
    currentProfile: 'UserProfile' // 当前画像，供模型做「增量 vs 全量」判断
  },
  outputSchema: {
    updates: ProfileUpdate[],    // 增量更新列表
    personaPatch?: string,       // 对 persona 长文本的修订建议
    confidence: number           // 本次抽取置信度 0~1
  },
  prompt: '你是基于用户交互抽取「用户画像」的抽取器。给定当前画像与一段交互，'
        + '只输出相对当前画像的【增量】（新增/修正/增强证据），不要重复已有内容。'
        + '严格 JSON。字段仅限：interests / expertise / preferences / goals / role / persona。'
}
```

### 4.2 抽取触发点（在交互中完善画像）

| 触发场景 | 触发入口 | 抽取内容重点 |
|---|---|---|
| 首页/笔记**问答** | `ask` / `NoteAIChat` 每轮响后 | 兴趣主题、提问深度、协作偏好（tone/depth） |
| **知识库诊断** | `diagnose` 结果返回后 | 知识结构弱点、关注领域缺口、目标线索 |
| **笔记保存 / 快速笔记** | `quick-note` / `writeNote` 后 | 标签聚类 → 兴趣主题、领域归属 |
| **灵感工坊** | `daily-insight` / 灵感方向选择 | 用户偏好的思考范式（盲区/补充/换框架） |
| **手动修正** | 设置页「我的画像」编辑 | 用户显式覆盖，优先级最高 |

### 4.3 合并策略（profile-service.merge）

```ts
function mergeProfile(cur: UserProfile, delta: ProfileExtractResult): UserProfile {
  const next = clone(cur);
  for (const u of delta.updates) {
    applyUpdate(next, u);          // 按字段路径写值
  }
  // 主题权重衰减 + 新证据加权
  next.interests = recomputeWeights(next.interests, now);
  // persona 长文本：若有 patch 则 LLM 重写或拼接（低频，避免抖动）
  if (delta.personaPatch) next.persona = reconcilePersona(next.persona, delta.personaPatch);
  // 审计
  next.audit.push(...buildAudit(delta));
  // 整体置信度：滚动平均
  next.confidence = rollConfidence(cur.confidence, delta.confidence);
  next.updatedAt = now;
  return next;
}
```

**去冲突与优先级**：`manual`（用户手改）> `diagnose`（结构化结论）> `note-tag`（聚类事实）> `chat`（自然语言信号，权重最低）。同一字段多条证据取加权平均。

**衰减机制**：`interests.weight` 与 `recentFocus` 按时间指数衰减（半衰期 ~30 天），长期不提的主题自然淡出；`basics` / `preferences` 事实类不衰减，除非有更高优先级证据覆盖。

## 5. 画像在 AI 协作中的应用（注入方式）

### 5.1 System 上下文注入（统一由 AIHub 完成）

在 `AIHub` 组装 `system` 提示词时，把画像渲染为固定区块，附加在 `BASE_SYSTEM` 之后：

```
【用户画像 · 长期上下文】
- 身份：{basics.role}，关注领域：{basics.domains}
- 当前目标：{basics.goals}
- 协作偏好：回答风格={preferences.tone}，深度={preferences.depth}，
  主动度={preferences.proactivity}，要求引用来源={preferences.citeSources}
- 近期聚焦：{recentFocus.top3 主题}
- 领域熟练度：{expertise 摘要，用于决定举例深浅}
- 用户画像简述：{persona}
（以上为你的长期记忆，请在回答中自然运用，不要显式复述「根据您的画像」）
```

注入通过 `PromptRegistry` 的变量机制实现（`{{userProfile}}` 占位），与库级 `AI_CONFIG.md`、用户高级提示词同优先级治理。

### 5.2 分场景应用

| 场景 | 画像如何利用 |
|---|---|
| **首页问答 / 笔记对话** | 用 `tone`/`depth`/`proactivity` 调节回答形态；用 `interests` 做联想；用 `expertise` 决定举例深浅 |
| **知识库诊断** | 诊断 Prompt 注入 `goals` 与 `domains`，让诊断围绕「用户目标」而非泛泛健康检查；结论回灌画像 |
| **智能写作 / 锻造卡片** | 用 `persona` + `domains` 保持语气与术语一致；卡片默认归属目录参考 `interests` 聚类 |
| **灵感工坊** | 根据用户已选「思考范式」偏好（盲区/补充/换框架）默认排序；灵感主题贴合 `recentFocus` |
| **每日灵感一现** | 结合 `timezone` 与历史点击，挑时段推送；主题从 `interests` 采样 |

### 5.3 主动建议（proactivity）

当 `preferences.proactivity >= balanced` 且画像检测到「信号足够强但未行动」时（如某主题连续 3 天高频出现但无对应笔记归类），AI 在回答末尾以**建议气泡**形式提示（承接「先建议后确认」铁律，不直接执行）。

## 6. 渲染层配套

### 6.1 「我的画像」查看/编辑面板

新增 `UserProfilePanel.tsx`（入口挂在设置页或主页侧栏「画像」图标）：
- 展示 `basics` / `interests`（带权重条）/ `preferences`（可切换）/ `persona`（只读长文）。
- 每个动态字段标注「来源」与「最近更新时间」（来自 `audit`）。
- 提供「清空画像」「导出/导入」按钮（本地文件）。

### 6.2 对话中的轻提示

- 当画像置信度 `< 0.3` 时，首次对话引导用户填 `basics`（一次性的轻量引导，不强制）。
- 当画像发生重大更新（如新增高权重主题），在 `StatusBar` 或 toast 显示「已更新你的画像：+AI 工程」可点击查看。

### 6.3 Hook 封装

```ts
// renderer/hooks/useUserProfile.ts
function useUserProfile(kbId?: string) {
  const [profile, setProfile] = useState<UserProfile>();
  const refresh = () => window.forge.profile.get(kbId);
  const update = (patch: Partial<UserProfile>) => window.forge.profile.update(kbId, patch); // 手动修正
  return { profile, refresh, update };
}
```

| `renderer/components/UserProfilePanel.tsx`（新） | 画像面板 |

### 7.2 与 AIHub 的衔接（改动最小）

在 `ai-service.ts` 组装 system 提示词处（现有 `BASE_SYSTEM` 之后）追加：

```ts
const profile = await profileService.get(kbId);
const profileBlock = profile ? renderProfileBlock(profile) : '';
const sys = `${BASE_SYSTEM}\n${profileBlock}\n${kbConfigBlock}`;
```

在 `AIHub.run` 返回后（或 Session 阶段性 flush 时）异步触发：

```ts
// 不阻塞主响应
void this.run({
  skill: 'profile-extract',
  input: { history: turns, trigger, currentProfile: profile },
  kbId
}).then(res => profileService.update(kbId, res.data));
```

> 抽取失败 / 模型未配置：静默跳过，**绝不影响主对话**；未配模型时可用 `localFallback` 做规则化轻抽取（关键词→interests 权重）。

## 8. 隐私与安全

1. 画像文件位于本地 `.forge/`，随知识库加密/备份策略一致，不主动外传。
2. 任何写类操作（即使是画像驱动的归档建议）仍走「先建议后确认」；画像只影响**回答内容**，不直接触发文件变更。
3. `UserProfilePanel` 提供「清空」与「逐字段删除」，用户完全掌控。
4. 画像在 system 提示词中以「长期记忆」呈现，要求模型不显式复述「根据您的画像」，避免用户感知突兀。

## 9. 分阶段落地路线

**阶段 A · 数据层 + 注入（最小可用）**
- 新增 `profile.ts` 类型 + `profile-service.ts`（读写/合并/衰减）。
- `ai-service.ts` 在 system 注入 `renderProfileBlock`；`UserProfilePanel` 只读展示 + 手动编辑 `basics`/`preferences`。
- 来源：`manual` 优先，解决「画像为空也能用」。

**阶段 B · 自动抽取闭环**
- 落地 `profile-extract` Skill；在 `ask` / `diagnose` / `note-save` 后异步抽取。
- `interests` / `expertise` / `persona` 自动演进；`audit` 可视化。

**阶段 C · 个性化深化**
- 分场景应用（§5.2）细化：诊断围绕目标、灵感贴合近期聚焦、主动建议气泡。
- `RecentFocus` 衰减调优；置信度门控引导。

**阶段 D · 跨库与导入导出**
- App 级底画像 + 知识库级叠加；画像导出/导入/迁移。

## 10. 收益小结

1. **AI 从「一次性问答」升级为「懂用户的长期伙伴」**：每次交互都在让管家更懂你。
2. **复用现有体系**：画像抽取 = 一个 Skill，注入 = 一段 system 变量，零架构冲突。
3. **隐私可控、可解释、可撤销**：本地存储 + 审计 + 手动接管，符合产品调性。
4. **飞轮效应**：画像越准 → 回答越贴合 → 用户越愿意交互 → 画像越丰满，形成正循环。
5. **诊断/灵感/写作全面增益**：同一份画像驱动所有 AI 协作场景，一致性提升。
