# 锦囊笔记存储实现方案

> 基于当前 `forgenote/src` 实现梳理。本文档说明笔记正文、SQLite 配置库、全文检索索引、双向链接索引、AI 会话与审计等各层存储的设计与落盘方式。

## 1. 总体分层

| 层 | 存储介质 | 位置 | 进程 | 职责 |
| --- | --- | --- | --- | --- |
| 笔记正文 | 文件系统（Markdown） | 用户选择的知识库根目录 | 主进程 `fs-service` | 笔记原文、frontmatter |
| 配置/元数据 | SQLite (`better-sqlite3`) | `userData/forgenote/config.db` | 主进程 `store` | KB 列表、AI 预设、审计、KV |
| 全文检索索引 | 内存（`search-service`） | 进程内存 + SQLite `app_config.key='searchIndex'` 持久化 | 主进程 | 关键词/文件名检索 |
| 双向链接索引 | 内存（`link-index`） | 进程内存 | 主进程 | `[[笔记名]]` 出链/反链解析 |
| 目录树 / 模板元数据 | 内存（`kb-service`）+ `.kb_template.json` | 知识库根目录隐藏文件 | 主进程 | 树结构、模板目录 |
| AI 会话 / 消息 | 文件系统（JSON，每会话一个文件） | 知识库 `.AI_TALK/` | 主进程 `session-store` | 多轮对话记录 |

设计要点：**正文永远以 Markdown 文件为真源（source of truth）**，所有内存索引都是派生数据，可通过对知识库目录重新扫描重建。

## 2. 笔记正文（Markdown 文件）

### 2.1 落盘路径

由 `fs-service` 操作，路径规则：

- 知识库根目录由用户在添加 KB 时选择（`KnowledgeBase.rootPath`）。
- 笔记路径即相对根目录的 `notePath`，如 `01 项目/周报.md`。
- 写文件统一走 `utils/fs.atomicWrite`（先写临时文件再 `rename`），避免半写损坏。
- 隐藏目录 / 文件（`.` 开头，`isHidden`）参与扫描但不在 UI 暴露；`.AI_TALK/`、`.AI_CONFIG.md`、`.kb_template.json` 均为隐藏元数据。

### 2.2 读取与解析

`fs-service.readNote(kbId, notePath)`：

- 拼接绝对路径后用 `safeJoin` 防目录穿越。
- 读取全文，解析 YAML frontmatter（以 `---` 包裹），返回：

```ts
interface NoteContent {
  path: string;
  content: string;            // 正文（不含 frontmatter）
  frontmatter: Record<string, unknown>;
  createdAt?: number;
  updatedAt?: number;
}
```

- frontmatter 的 `createdAt` / `updatedAt` 由 `frontmatterService` 维护；若缺失则回退到文件 mtime（`stat.mtimeMs`）。

### 2.3 写入与同步

- `writeNote`：原子写 + 更新 frontmatter 的 `updatedAt` + 刷新内存索引（`searchIndex.addOrUpdate` / `linkIndex.updateOutlinks`）+ 触发文件监听事件。
- 移动 / 重命名：`moveNote` 通过 `fs.rename`，同步更新 link-index 的 rename 映射，并广播事件让引用该笔记的链接仍可解析。
- 删除：`fs.unlink` + 从两个索引移除。

## 3. SQLite 配置库（`store.ts`）

### 3.1 数据库文件

- 引擎：`better-sqlite3`（同步 API）。
- 路径：`app.getPath('userData')/forgenote/config.db`。
- 模式：`db.pragma('journal_mode = WAL')`，提升并发读写安全性。
- 初始化：`initStore()` 在 app 启动早期调用，建表（IF NOT EXISTS）。

### 3.2 表结构

```sql
-- 知识库注册表
CREATE TABLE kbs (
  id          TEXT PRIMARY KEY,
  name        TEXT NOT NULL,
  root_path   TEXT NOT NULL,
  template_id TEXT,
  created_at  INTEGER NOT NULL
);

-- 通用键值配置（JSON 序列化）
CREATE TABLE app_config (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);

-- 知识库级 AI 提示词预设（复合主键）
CREATE TABLE ai_presets (
  kb_id  TEXT NOT NULL,
  name   TEXT NOT NULL,
  content TEXT NOT NULL,
  active INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (kb_id, name)
);

-- 审计 / 操作日志（支持撤销）
CREATE TABLE audit (
  id      TEXT PRIMARY KEY,
  ts      INTEGER NOT NULL,
  kb_id   TEXT,
  action  TEXT NOT NULL,
  payload TEXT NOT NULL,
  undone  INTEGER NOT NULL DEFAULT 0
);
```

### 3.3 各表用途

- **`kbs`**：已挂载的知识库清单。由 `listKBs / addKB / removeKB / getKB / updateKBTemplate` 维护。注意：正文不在 SQLite，这里只存「指针」（rootPath）+ 模板绑定。
- **`app_config`**：通用 KV。AI 服务配置、当前激活模型、检索索引等都以 `key → JSON` 形式存放（如 `key='searchIndex'` 持久化整张检索索引）。`setConfig/getConfig` 自动 JSON 序列化/反序列化。
- **`ai_presets`**：每个知识库一份提示词预设（`AIConfigPreset { name, content, active }`），复合主键 `(kb_id, name)`，支持多预设 + 一个 active。
- **`audit`**：操作审计，`payload` 为 JSON。`action ∈ {move, insertLink, forge, applyTemplate, removeTemplate}`。`undone` 标记是否已撤销，供 `audit-service.undo` 反向执行文件操作。

### 3.4 关键 API（`store.ts`）

```ts
initStore()
listKBs() / addKB(kb) / removeKB(id) / getKB(id) / updateKBTemplate(id, templateId)
getConfig<T>(key, def?) / setConfig(key, value)
listPresets(kbId) / upsertPreset(kbId, preset) / setPresetActive(kbId, name)
addAudit(entry, kbId?) / listAudit(kbId, limit) / markAuditUndone(id)
```

## 4. 全文检索索引（`search-service.ts`）

### 4.1 数据结构

内存 `Map<kbId, Map<notePath, IndexEntry>>`，其中：

```ts
interface IndexEntry {
  noteName: string;
  notePath: string;
  lower: string;        // 小写正文（用于匹配）
  templateDirId?: string;
  tags: string[];
  titleHits: string[];  // 标题命中关键词
  contentHits: string[];// 正文命中关键词
  linkHits: string[];
  size: number;
}
```

派生自正文扫描：标题命中（文件名/标题）、正文命中、标签（`#tag`）、链接（`[[...]]`）。

### 4.2 写入与重建

- 增量：`addOrUpdate(kbId, notePath, entry)` / `remove(kbId, notePath)`。
- 全量重建：`buildTree`（目录树）时顺带 `buildIndex` 重新扫描整个知识库目录。
- **持久化**：`saveIndex()` 把整张 Map 序列化进 SQLite `app_config.key='searchIndex'`，启动时 `loadAllIndices()` 反序列化，避免每次冷启动全量扫描磁盘。

### 4.3 查询与重排

`query(kbId, q, opts?)`：

- 拆词 → 在 `titleHits / contentHits / tags / linkHits` 上匹配。
- 打分：标题/标签命中权重高于正文；返回 `SearchResult[]`：

```ts
interface SearchResult {
  notePath: string;
  noteName: string;
  snippet: string;        // 命中上下文片段
  templateDirId?: string;
  matchType: 'title' | 'content' | 'tag' | 'link';
  score: number;
}
```

- 上层 `ai-service.rerankHits`（#1 检索重排）在召回基础上，按「查询词词面重叠 + 标题/匹配类型加权」二次打分并截断到 top-N，使进入 AI context 的引用更聚焦。

## 5. 双向链接索引（`link-index.ts`）

纯内存 `Map<kbId, Map<notePath, Set<target>>>`：

- `updateOutlinks`：笔记保存时抽取 `[[目标]]` 写入出链集合。
- `getBacklinks`：反向遍历求所有指向某笔记的源笔记（反链面板）。
- `resolve`：将 `[[笔记名]]` 解析为真实 `notePath`，支持完整路径 / 去 `.md` / 仅 basename 三种匹配，便于跨目录链接。
- `renameNote`：重命名时同步迁移出链映射，保证链接不断。

## 6. 目录树与模板元数据（`kb-service.ts`）

- `treeCache`：`Map<kbId, { tree: TreeNode; ts }>` 内存缓存，UI 直接读。
- `metaCache`：从根目录隐藏文件 `.kb_template.json` 解析模板目录（`{ id, name, icon, color, folderName }`），再与实际目录扫描（`/^(\d{2})\s+(.+)$/`）匹配。
- `.AI_CONFIG.md`：隐藏文件，存放 AI 模型内部设定（仅模板设置与 AI 调用使用）。

`TreeNode` 结构（含 `id/name/path/kind/size/children` 等）用于渲染文件树。

## 7. AI 会话存储（`session-store.ts`）

- 每个会话一个 JSON 文件，落在知识库隐藏目录 `.AI_TALK/<convId>.json`。
- 文件内容：`{ id, kbId, title, createdAt, updatedAt, turns: AITurn[] }`。
- `AITurn`：

```ts
interface AITurn {
  role: 'user' | 'assistant' | 'tool';
  text?: string;
  ts: number;
  refs?: AIRefHit[];
  skill?: string;
  tool?: ToolActivity;   // 智能体工具调用轨迹
  pending?: { type: string; payload: unknown };
}
```

- 读写：`loadSession / saveSession / appendTurn / ensureSession`，全部走 `utils/fs.atomicWrite`，避免并发半写。
- 会话清单（`.AI_TALK/index.json`）记录 `convId → meta`，供历史列表展示。

> 会话持久化在文件系统而不是 SQLite：会话体可能较大且以整文件读写为主，文件化更易调试、可随知识库目录一起备份/迁移。

## 8. 审计与撤销（`audit-service.ts`）

- 任何可撤销操作（移动、插入链接、锻造新卡片、套用/移除模板）先经 `auditService.record` 写入 SQLite `audit` 表。
- `undo(kbId, auditId)` 根据 `action` + `payload` 反向操作文件：
  - `move`：`fs.rename` 移回原路径；
  - `insertLink`：正则删除 `[[target]]` / `[[target|alias]]`；
  - `forge`：`fs.unlink` 删除新卡片。
- 撤销后 `markAuditUndone` 置 `undone=1`，不可重复撤销。

## 9. 持久化与一致性总结

1. **真源优先**：笔记正文 = Markdown 文件；SQLite 仅存指针与配置；索引皆为派生、可重建。
2. **原子写**：笔记、会话、模板写入均经 `atomicWrite`（临时文件 + rename）。
3. **索引重建**：重扫知识库目录即可重建 `search-index` 与 `link-index`；检索索引另落 SQLite `app_config` 以加速冷启动。
4. **WAL 模式**：SQLite 开启 WAL，兼顾崩溃安全与读并发。
5. **事件驱动**：文件变更经 `fs.watch` 广播 `FSChangeEvent`，前端实时刷新树/检索。

## 10. 潜在优化方向

- **检索索引分库**：当前整张 `searchIndex` 序列化为单条 `app_config`，知识库大时反序列化成本高，可改为 SQLite 独立表（`idx_entries`）按 `kb_id/note_path` 行存。
- **frontmatter 独立索引**：`createdAt/updatedAt/tags` 可入 SQLite，避免每次读文件 stat。
- **会话存储可选项**：长会话可迁移到 SQLite（`better-sqlite3`）以统一存储层，但需权衡文件化备份便利。
- **链接索引持久化**：`link-index` 现为纯内存，重启依赖重扫；可随检索索引一起落盘。
